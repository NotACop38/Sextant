# Sextant v0.1.0: parsers you can trust for unknown binary formats

*A short write-up for the launch announcement. Adapt freely for a blog post, a
Discussions "Announcements" entry, or a forum thread.*

## The gap

Reverse engineers constantly hit undocumented binary: proprietary file formats,
save files, firmware blobs, industrial and IoT protocols, malware traffic.
Working out the layout by hand is slow, and the existing tools each solve only
part of the problem. Manual editors like Kaitai Struct, ImHex, and 010 make you
write the spec yourself. Academic protocol-reverse-engineering tools infer
structure but emit raw field boundaries, often need expert hints, and tend to
choke on sub-byte fields. The recent wave of LLM tools has gone almost entirely
into disassembly, not format structure.

Nobody sits in the middle. Sextant is built for that gap: statistical inference
for the boundaries, an optional language model for the semantics, and, the part
everyone is missing, **verification that the result actually parses the input**.

## The idea: a falsifiable hypothesis

The center of Sextant is the **Format Hypothesis IR**: a structured, executable
description of "what we think this format is". Fields have offsets, sizes, types,
and roles (magic, version, length, count, offset, checksum, enum, payload), and
relationships between them (a length governs a run of bytes; a checksum covers a
range).

Crucially, the IR is not a document, it is a program. Sextant has a native Rust
**executor** that runs an IR directly against raw bytes, producing concrete
field instances or a localized failure, and a **scorer** that grades the fit on
coverage, consistency (do the length, count, offset, and checksum relationships
hold?), and generality across the whole sample set. The executor and scorer are
JVM-free, network-free, and bounded: recursion depth, array length, and a
wall-clock cap mean no input can panic, hang, or blow up memory.

## The loop: propose, test, keep only what verifies

Inference is a generate-test-refine loop:

1. **Statistical inference** proposes candidate structure: entropy and n-gram
   boundaries, multi-sample alignment (the same math as aligning biological
   sequences), magic detection, and length/count/offset/checksum heuristics
   across endianness and width hypotheses.
2. **The optional model pass** adds semantics on top: names, roles, types, enum
   meanings, a format-family guess, and refinement proposals expressed as edits
   to the IR.
3. **The executor disposes.** Every proposal, statistical or model-driven, is
   executed and scored. A change is accepted only if the verified parse score
   does not regress on the full sample set. The model proposes; the executor
   decides.

This is the property that makes the output trustworthy. A confident-sounding
guess is worthless if it does not parse the bytes, so Sextant never ships one.
The chosen IR parses every sample by construction, and the report says honestly
what was verified and what is merely inferred.

Run it with `--no-llm` and the whole thing is local and offline: the statistical
engine and the executor stand on their own, and zero bytes leave the machine.

## What you get

Off the verified IR, Sextant exports real, editable parsers:

- **Kaitai Struct** (`.ksy`), which compiles to C++, Python, Java, Go, Rust, and
  more,
- **ImHex** patterns, **Wireshark** Lua dissectors, **010 Editor** templates,
- and an **annotated hex view** that reads any sample through the inferred
  structure.

On the bundled ground-truth corpus, the statistics-only core (no model) clears
the project's targets: field-boundary F1 of 0.956, a 60% perfection rate, and
100% parser validity, every number generated by `sextant bench`, not written by
hand.

## Try it

```sh
cargo install sextant-re        # installs a binary named `sextant`
sextant infer ./samples/*.bin --no-llm --out report.json
sextant inspect report.json --sample ./samples/one.bin
sextant export report.json --format kaitai --out format.ksy
```

v0.1.0 is the first public release and is pre-1.0, so interfaces may still
change. Issues describing formats or protocols you would like to reverse, and
