# Project review, 2026-09-12

Baseline: `57c2161f14de5aa7c943ebdc34230c502afb3069`.
Scope: product claims, native verification, hostile-input limits, parser exports,
benchmark inputs, CLI file writes, optional subprocesses, and delivery checks.
This was a targeted source and regression review, not a proof of complete safety.

## Product decision

Keep the native Rust executor and provider-neutral IR. They make structural
hypotheses falsifiable without requiring a network service or external compiler.
Focus the product on helping analysts test and revise hypotheses. Claims of
universal parser verification, semantic certainty, a fixed percentage of analyst
work saved, or superiority over competitors were unsupported and are removed.

The CLI can now report success only when every retained sample is fully covered,
all constraints pass, and no gaps, overlaps, or trailing bytes remain. Failed
verification still produces a diagnostic report. A score of 1.0 can still describe
an opaque payload; it is not proof that the format was understood.

## Remediated findings

| Area | Baseline problem | Change and regression evidence |
|---|---|---|
| Refinement | Aggregate score gains could sacrifice a previously parsed sample | Require nondecreasing finite fit and preserve each successful or fully verified sample; uneven-length sample regression |
| CLI output | A dangling output symlink could create a file outside the working directory | Atomic `create_new` without `--force`; existing-file and dangling-symlink regressions |
| IR validation | Deep recursion and pairwise overlap diagnostics could exhaust resources before limits were applied | Shape preflight, indexed references, bounded diagnostics, and sorted overlap checks; deep, wide, overlapping, and large-enum regressions |
| Native output | Repeated field names and constraint metadata could multiply allocations | Explicit owned-output budget and borrowed scope metadata; allocation and repeated-constraint regressions |
| Inspection | Overlap coloring used quadratic range searches | Endpoint sweep preserving last-painted priority, direct segment lookup, and bounded rendering |
| Generated comments | Newlines in checksum references could escape comments in ImHex and 010 source | Shared comment escaping with valid hostile-reference regressions |
| Generated Lua | Missing delimiters and zero-sized repeated elements could loop or misparse | Delimiter errors, progress checks, shared work limits, and runtime regressions |
| Export fidelity | Some legal IR structures emitted lossy target code | Capability rejection for unsupported layouts; Kaitai byte-bounded substreams; external runtime regressions |
| Cross-validation | Python imported from the analysis directory; scratch samples used ordinary temporary files; child execution was unbounded | Python isolated mode and controlled cwd, private temporary directory, deadline/output caps, full consumption, and compiler-pin validation |
| Benchmark input | Small manifests could request huge record expansion; file reads silently clipped samples | Manifest, aggregate byte and field budgets; checked field expansion; confined paths and exact sample sizes |
| Reporting | Signed fields were labeled unsigned; model metadata could describe a path not used | Signed type labels and metadata reflecting actual statistics-only execution |

The dangling-symlink, uneven-sample refinement, nested-array validation, and
exporter regressions were reproduced against the baseline before their fixes.
The regression tests are kept beside the affected implementation. Final independent
review also reproduced exporter failures involving future local fields shadowing
ancestor references, normalized enum identifiers, and empty sanitized reference
names. The supported export subset now rejects those ambiguous cases.

## Qualification still required

- The benchmark uses 21 development samples across four synthetic formats and
  PNG. It measures inference on the same samples used to construct the hypothesis.
  Full PRD corpus coverage, held-out generalization, and competitor evaluation
  remain open. JSON `parser_validity` means native IR validity for compatibility.
- Kaitai/Python and Lua tests provide selected external runtime evidence. Lua
  uses a checked Wireshark API adapter; actual Wireshark, ImHex, and 010 Editor
  runtime qualification remains open. Unsupported target
  constructs return errors rather than silently weakening their layout.
- Semantic labels and confidence are suggestions backed by stated evidence,
  not authenticated facts or calibrated probabilities. Imported reports are
  untrusted and do not establish that their stored scores were recomputed.
- Alignment is positional. TCP analysis uses segment payloads without stream
  reassembly. The timeout applies to each native execution, not the whole run.
- Model caching is opt-in; logical-call counts include possible HTTP retries,
  and optional spend accounting is not a hard provider spending cap.
- External compiler/runtime execution is optional and outside the native offline
  boundary. Its executable installation must be trusted.
- No GitHub release is published as of this review; packaging workflows and dry
  runs do not establish distribution readiness. Registry installation was not
  verified. Discussions is disabled; issues are the current contribution channel.

The engineering checklist leaves these acceptance gaps open. No release,
announcement, model request, or live protocol transmission is part of this review.

## Reference decisions

- Rust documents atomic refusal of existing entries for
  [`OpenOptions::create_new`](https://doc.rust-lang.org/std/fs/struct.OpenOptions.html#method.create_new).
- Kaitai's [substream documentation](https://doc.kaitai.io/user_guide.html) distinguishes
  a size-bounded nested structure from applying a size separately to each repeated
  element; the exporter now preserves that distinction.
