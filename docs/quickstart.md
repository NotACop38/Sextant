# Quick start

This walkthrough takes an unknown binary blob and produces a verified parser in
three commands. It uses the bundled TLV (tag-length-value) corpus, so it works
on a fresh checkout with no setup beyond building the binary. Every command here
runs fully offline.

If you have not built Sextant yet, see [Installation](installation.md). The rest
of this page assumes the binary at `./target/release/sextant`.

## The samples

The repository ships a small ground-truth corpus under `corpus/`. The TLV format
is a custom, controlled format: a five-byte magic, a one-byte record count, then
a sequence of records, each a one-byte tag, a two-byte little-endian length, and
that many payload bytes.

```bash
ls corpus/tlv/samples
# sample_01.tlv  sample_02.tlv  sample_03.tlv
```

Pretend you do not know any of that. Sextant will work it out from the bytes.

## Step 1: infer

```bash
./target/release/sextant infer corpus/tlv/samples --no-llm --out report.json
```

You will see something like:

```
Ingested 3 samples (61 bytes total).
  corpus/tlv/samples/sample_01.tlv: 21 bytes
  corpus/tlv/samples/sample_02.tlv: 24 bytes
  corpus/tlv/samples/sample_03.tlv: 16 bytes

Best hypothesis: candidate-chunked (fit score 1.000)
  coverage 1.000  consistency 1.000  generality 1.000
  mode: statistics-only (no language model, no network egress)
Field map:
  magic: magic, bytes, 5 bytes (confidence 1.00)
  count: count, u8, 1 bytes (confidence 0.85)
  records: unknown, array, to end (confidence 0.85)
    record: unknown, struct, from fields (confidence 0.75)
      tag: enum, bytes, 1 bytes (confidence 0.50)
      length: length, u16 little-endian, 2 bytes (confidence 0.90)
      data: payload, bytes, derived from length (confidence 0.70)
Refinement: no improving change was found (already converged).

Wrote report to report.json
```

The fit score of 1.000 means the inferred structure parses every sample with
full coverage, no contradictions, and the same shape across all of them. The
per-field confidence values are honest: the length relationship is verified and
scores high, while the meaning of the one-byte tag is a softer guess and scores
lower.

The `--no-llm` flag guarantees this run is statistics-only with zero network
egress. See [Privacy and the `--no-llm` story](privacy.md).

## Step 3: export

Generate a runnable parser from the verified report. Kaitai Struct is the
primary target:

```bash
./target/release/sextant export report.json --format kaitai --out tlv.ksy
```

The first lines of `tlv.ksy`:

```yaml
# Generated by Sextant. Edit freely.
meta:
  id: candidate_chunked
  endian: le
seq:
  - id: magic
    contents: [0x53, 0x54, 0x4c, 0x56, 0x01]
    doc: 'role: magic'
  - id: count
    type: u1
    doc: 'role: count'
  - id: records
    type: record
    repeat: eos
```

You can also export an ImHex pattern, a Wireshark Lua dissector, or a 010 Editor
template:

```bash
./target/release/sextant export report.json --format imhex     --out tlv.hexpat
./target/release/sextant export report.json --format wireshark --out tlv.lua
./target/release/sextant export report.json --format 010       --out tlv.bt
```

## What just happened

Sextant ingested the samples, generated candidate structures using statistical
inference, executed each candidate natively against the bytes, scored the fit,
and picked the best. The exported parser is not a guess: it is generated from a
hypothesis that parsed every sample. See [How it works](how-it-works.md) for the
detail.
