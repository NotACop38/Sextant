### Inference

- Statistical inference that segments each header with a two-part minimum
  description length code and solves total-length, remaining-length, and count
  relations in closed form. Candidate families cover fixed layouts, a size
  field governing the rest of the sample (with the governed body typed as a
  nested section when that verifies), counted records, sequential regions
  confirmed by a following marker, length-prefixed chunk streams with
  per-record checksums, offsets to invariant markers, typed prefixes, and
  magic-only and opaque fallbacks.
- Candidates are ranked by full verification, then fit, passed checksums,
  encoded relations, and a description-length structure measure, and the
  ranking is deterministic run to run.
- A heuristic refinement loop (endianness swaps, width swaps, and boundary
  nudges) that keeps a change only when the verified fit does not regress and
  no previously parsed sample is lost.
- An optional model pass, `sextant infer --provider <anthropic|openai|ollama>`,
  in builds with the `llm` feature. The model proposes names, roles, types, and
  size rules as structured output; each proposal is applied only when the
  native executor verifies that the fit does not regress and no sample loses a
  passing check. Nothing is sent without `--provider`. Reports record model
  usage, including why a failed call contributed nothing. Setting
  `SEXTANT_MODEL_CACHE_DIR` caches responses on disk, keyed by a hash of the
  exact request, so a repeated run makes no provider call.
- Protocol inference from classic pcap and pcapng captures: payload
  extraction by transport and port, message clustering, request and response
  association, and detection of message type, sequence, and length fields.

### Verification

- The Format Hypothesis IR: formats, structures, fields, size and count rules,
  offsets, roles, constraints, evidence, and confidence, with validation that
  gives located errors and lossless JSON. A struct may carry a size rule, which
  makes it a bounded region, and every format that validates can be saved in a
  report and read back.
- A native executor and scorer with no JVM, compiler, or network dependency.
  Scores break down into coverage, consistency, generality, and a structure
  measure; explained, gap, and trailing bytes partition every sample.
  Checksums: CRC-32 (ISO-HDLC), CRC-16 (ARC), additive byte sum, and XOR.
- Limits on recursion depth, array length, field count, owned output bytes,
  total work, and wall-clock time, so no input can cause a panic, a hang, or
  unbounded allocation.

### Outputs

- A JSON report (schema version 1.1, committed at `schemas/report.schema.json`)
  with the chosen IR, per-field evidence and confidence, the score breakdown,
  the per-sample breakdown, the refinement history, and run metadata.
- `sextant inspect`, an annotated hex view of a sample read through a report.
- Exporters for Kaitai Struct (the primary target, with optional
  cross-validation through a local Kaitai compiler and Python runtime),
  Wireshark Lua, ImHex, and 010 Editor. Each exporter refuses layouts it cannot
  preserve, sanitizes every identifier and comment derived from input, and
  avoids the target's reserved words.

### Benchmark

- A ground-truth corpus of 16 real and purpose-built file formats in three
  tiers: development (tuned against), validation (held out, evaluated once, and
  then used to find one generic defect), and held-out (never examined before
  the published run). Modbus/TCP and a toy protocol cover the protocol track.
- `sextant bench` and `sextant-bench` report field-boundary precision, recall,
  and F1 over interior boundaries, the perfection rate, role and type accuracy,
  native validity, and the structure measure per tier, with regression floors
  enforced in CI and the PRD Section 15 targets reported whether met or not.
  The README block is generated by the harness and checked by a test.

### Security and robustness

- `cargo-fuzz` targets for ingestion, the IR and report JSON, the executor,
  inference, capture parsing, and each exporter, plus property tests for the
  parse invariants and resource bounds.
- Ingestion never follows a symlink below a named root, refuses a `..` after a
  wildcard, refuses FIFOs and other special files, caps bytes, entries, and
  files, and escapes untrusted text
  (control, bidirectional, and invisible characters) in all terminal output.
- Output files are created atomically and never overwrite an existing file or
  follow a symlink without `--force`.
- Model credentials come only from the environment or a config file, never
  from a flag; on Unix a config file readable by group or others is refused.
  The response cache is written atomically, owner-only, and never follows
  symlinks. Plain `http` is refused for keyed providers except on loopback.
- A default build of the CLI links no network code at all.

### Distribution

- CI on Linux, macOS, and Windows, with pinned action versions, supply-chain
  checks (`cargo deny`, `cargo audit` for both lockfiles), an API
  documentation build with warnings as errors, fuzz smoke runs, runs of the
  documented examples, and external runtime tests for the Kaitai and Lua
  exporters.
- A tag-driven release workflow that builds the CLI with the model providers
  for x86_64 Linux (glibc 2.34 or newer, and a static musl build), macOS on
  Intel and Apple silicon, and Windows, publishes SHA-256 checksums, and marks
  SemVer prereleases as GitHub prereleases. Install scripts for Unix and
  Windows and a Homebrew formula template follow the release artifacts.
- crates.io metadata for every crate; the CLI crate is named `sextant-re` and
  installs a binary named `sextant`.
